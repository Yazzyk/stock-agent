# 产品需求文档（PRD）

产品名：观澜 · Stock Agent（桌面端，Wails + Go + Vue3）
版本：v1.0 · 2026-11-10 · 状态：开发中（P0 范围）

## 1. 一句话定位

给个人 A 股研究者用的**本地研究台**：把盘前计划、盘中记录、盘后复盘、量化验证串成一条可回放的闭环，每次模型调用与数据访问都有审计。

卖点两句：

1. **可审计**——模型做了什么、读了什么、写了哪个文件，都能查到。不是"AI 说这只票好"。
2. **可扩展**——工具、面板、服务都是插件贡献的，加一个数据源或一个策略不用改内核。

## 2. 用户画像

### 画像 A：兼职研究者（主要用户）

- 32 岁，互联网/设计/金融周边岗位，入市 3–6 年，自有资金，持仓 5–10 只。
- 每天能投入 30–60 分钟：早上 10 分钟看计划，午休看一眼，晚上 20 分钟复盘。
- 有交易软件（同花顺/东方财富），也有自己的 Excel 或笔记，但**计划和复盘不连贯**：早上想的和晚上总结的常常不是同一件事。
- 痛点：信息太多、结论太散；AI 给的答案无法核对；回测跑出来的高收益不敢信。
- 愿意为"省时间 + 能验证"付费，不愿为"荐股"付费。

### 画像 B：短线题材研究者

- 27 岁，交易年限 2–5 年，日均盯盘 3–4 小时，关注涨停梯队、板块资金流、龙虎榜。
- 已有成熟的手工流程（自选分组、题材笔记、连板天梯），但**记录散落在截图和聊天记录里**。
- 需求：盘中快速记录触发事件；盘后能把"计划 vs 实际"对账；能回看某个题材的完整生命周期。
- 对"AI 帮他选股"高度警惕，对"AI 帮他记账、对账、算口径"接受度高。

### 画像 C：量化自学者（次要用户）

- 35 岁，会写 Python/Go，想验证均线、动量、资金流类规则。
- 需求：本地数据、可复现回测、明确的成本模型、过拟合检查。
- 痛点：开源回测框架默认零成本、用当前成分股回溯、样本外反复调参，结论不可信。

### 反画像（明确不服务）

- 想要"明天买什么"的人。
- 需要 Level-2 逐笔、需要分钟级高频撮合的人。
- 需要多人协作、需要云端同步持仓的人。

## 3. Jobs to be done

按"当我……我想……以便……"写，每条对应一个可验收的产物。

| # | Job | 产物 | 优先级 |
|---|---|---|---|
| J1 | 开盘前 10 分钟，我想把隔夜信息和自选股收敛成 3–5 个带触发条件的观察标的 | `plan.md` | P0 |
| J2 | 盘中，我想在条件成立的那一刻留一条带时间戳的记录，而不是收盘后凭记忆补 | `ticklog.md` | P0 |
| J3 | 收盘后，我想把计划与实际逐条对账，找出偏差原因 | `review.md` | P0 |
| J4 | 我想知道某个数字是哪来的（接口、口径、时间），不想再相信"AI 说" | 审计记录 + 数据来源标注 | P0 |
| J5 | 我想验证一个规则在过去 5 年是否成立，并且知道结论有多可信 | `report.md` + 五关自检 | P0 |
| J6 | 我想把同花顺自选同步过来，不想手工重建分组 | 同步结果（本地容器 → 网页 → 手工三级降级） | P1 |
| J7 | 我想看某只股票当前处于什么位置、板块资金是否支持 | K 线面板 + 资金流面板 | P1 |
| J8 | 我想让模型按我认可的方法论做事，而不是每次重新解释 | 技能库（`content/skills`） | P1 |
| J9 | 我想在换电脑后还留着历史计划与复盘 | 本地 sqlite + 导出 | P2 |

## 4. 功能矩阵

优先级定义：P0 = 没有它产品不成立；P1 = 第一个可用版本必须有；P2 = 有明确用户后才做。

### 4.1 行情与自选

| 能力 | 优先级 | 说明 |
|---|---|---|
| 个股/指数快照（批量） | P0 | 单批 ≤ 50 只，标注 `stale` |
| 日/周/月/分钟 K 线（含复权） | P0 | 复权口径必须显式传参 |
| 自选列表本地存储与分组 | P0 | 支持手工增删 |
| 同花顺自选同步（三级降级） | P1 | 本地容器 → 网页登录 → 手工导入 |
| 代码搜索（名称/拼音/代码） | P1 | 返回市场前缀 |
| 指标计算（MA/RSI/ATR/回撤） | P0 | 与 K 线同包提供 |

### 4.2 资金流与板块

| 能力 | 优先级 | 说明 |
|---|---|---|
| 个股资金流（主力/超大/大/中/小） | P0 | 新浪 `r0~r3` 成交额分档，净额 = in − out，主力 = `r0_net + r1_net`；单位元 |
| 板块资金流排名（行业/概念） | P0 | 明确"成分更新日期" |
| 板块列表与涨跌幅 | P1 | 与资金流交叉展示 |
| 资金流失真标注（大宗/停牌/新股） | P1 | 结论区必须出现 |

### 4.3 Agent 研究闭环

| 能力 | 优先级 | 说明 |
|---|---|---|
| ReAct 循环（工具调用 + 步数上限 + 取消） | P0 | 每步可审计 |
| 盘前/盘中/盘后/量化四个 worker | P0 | 对应 J1–J3、J5 |
| 会话日志可回放（append-only） | P0 | 事件只增不删，派生视图可变 |
| 工具调用预算与超时 | P0 | 24 次调用 / 单次 8s 网络超时 |
| 流式输出与中断 | P1 | 用户可随时停止 |
| 报告落盘到 `runs/<date>/` | P0 | 路径受 Guard 限制 |

### 4.4 渐进式披露（工具 / 技能 / 知识库）

| 能力 | 优先级 | 说明 |
|---|---|---|
| 工具三级披露：L1 摘要索引 → L2 schema → L3 执行 | P0 | 每次只把相关工具塞进上下文 |
| 技能库：`content/skills/<slug>/SKILL.md` | P1 | 6 个内置技能 |
| 知识库 RAG：`content/kb/*.md` | P1 | 10 篇，中文 bigram + TF-IDF，分数可复现 |
| 用户自定义技能目录 | P2 | `~/.guanlan/skills/` |

### 4.5 模型与设置

| 能力 | 优先级 | 说明 |
|---|---|---|
| 多 provider 配置（DeepSeek / OpenAI 兼容） | P0 | 密钥 AES-GCM 存本地，0600 |
| 模型连通性测试 | P1 | 显示延迟与错误原文 |
| 安全策略可视化（白名单/路径/限额） | P1 | 只读展示 + 可编辑 |
| 审计日志查看 | P0 | 时间/插件/动作/耗时/结果，脱敏 |

### 4.6 平台能力

| 能力 | 优先级 | 说明 |
|---|---|---|
| 插件清单与健康状态 | P0 | 未激活要给出原因 |
| 无界面任务（headless） | P0 | 验收与排障入口 |
| 导出（计划/复盘为 Markdown） | P2 | 已有文件，导出为打包 |

## 5. 明确非目标

写清楚不做什么，比写做什么更重要。

1. **不荐股**：不输出"买入/卖出/目标价"。所有结论是研究记录，不是建议。
2. **不承诺收益**：不展示"预期收益""胜率保证"，历史绩效必须带样本量与自检结论。
3. **不下单**：不接券商交易通道，不做委托、撤单、银证转账。代码里不出现任何下单接口。
4. **不做实时 Level-2**：不接逐笔委托与十档行情，分钟级已是上限。
5. **不做社区与跟单**：没有用户体系、没有大 V、没有组合跟买。
6. **不做云端同步**：数据只在本机 `~/.guanlan`，不上传。
7. **不预测点位**：不输出"明日支撑位 3200 点"这类数字预测。
8. **不做自动交易策略托管**：回测结论只用于研究，不自动执行。

## 6. 竞品差异

| 维度 | 同花顺 | 雪球 | go-stock（开源） | 观澜 |
|---|---|---|---|---|
| 定位 | 全功能行情终端 | 社区 + 组合 | 轻量行情 + AI 点评 | 本地研究闭环 |
| 数据广度 | 极强（含 Level-2） | 中 | 中 | 中（够研究用） |
| 计划→复盘闭环 | 无（靠用户自建） | 弱（发帖形式） | 无 | **有，且有固定产物格式** |
| 结论可审计 | 不涉及 AI | 不涉及 AI | 弱（AI 输出无来源） | **每次工具调用、数据来源、耗时都记录** |
| 方法论沉淀 | 无 | 社区经验帖 | 提示词硬编码 | **技能库 + 知识库，可版本化** |
| 回测诚实性 | 有回测但成本口径不透明 | 无 | 无 | **五关自检（未来函数/样本外/成本/幸存/敏感性）** |
| 扩展性 | 封闭 | 封闭 | 需改源码 | **插件契约：工具/面板/方法/服务四类贡献点** |
| 本地数据 | 云端为主 | 云端 | 本地 | **本地 sqlite，路径受控** |

差异结论：不比数据广度，不比社区热度。比的是**"你的研究过程能不能被复核"**。

同花顺解决"看到"，雪球解决"讨论"，go-stock 解决"快速看 AI 点评"。观澜解决"**做完一轮研究，能证明自己没骗自己**"。

## 7. 成功指标

产品层面（可测，不设虚荣指标）：

| 指标 | 目标 | 测法 |
|---|---|---|
| 首次盘前计划产出时间 | ≤ 10 分钟（从打开到 `plan.md` 落盘） | 手测 + 日志时间戳 |
| 计划→复盘闭环连续天数 | ≥ 5 个交易日 | `runs/` 目录检查 |
| 计划字段完整率 | 100%（四字段齐全） | 落盘前校验 |
| 工具调用审计覆盖率 | 100% | 审计条数 = 调用次数 |
| 回测报告自检表存在率 | 100% | 报告首节校验 |
| 数据源失败可解释率 | 100%（有降级或明确错误） | 错误文案检查 |

反指标（出现即视为回归）：

- 输出中出现"推荐买入""目标价""必涨"。
- 计划标的 > 5 个。
- 回测报告无成本明细。
- 审计中出现未脱敏密钥。

## 8. 约束与风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据源非官方接口变更 | 行情/资金流中断 | 多源降级（同花顺→腾讯→新浪），单块失败只降级该块并暴露健康状态 |
| 同花顺本地格式变化 | 自选同步失败 | 三级降级，失败时给明确指引，不静默 |
| 模型幻觉出数字 | 结论不可信 | 所有数字必须来自工具返回；报告要求标注来源 |
| 用户把研究当建议 | 合规风险 | UI 与文档统一措辞；非目标写进 PRD 与空状态文案 |
| 免费接口限流 | 请求失败 | 令牌桶 + 重试 ≤2 + 缓存 |
| 回测结论被误用 | 亏损归因 | 自检表前置；不通过不出结论 |
